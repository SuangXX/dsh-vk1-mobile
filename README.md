# DSH 余额挂件 · 移动端适配版

[VK-1 余额挂件](https://github.com/VKmich16/VK-1) 的 DSH 网页插件版，**加上 Android 手机端的适配补丁**。

| 部分 | 来源 | 许可 |
| --- | --- | --- |
| 行为逻辑、美术、音效、手感参数 | [VKmich16/VK-1](https://github.com/VKmich16/VK-1) | MIT（上游 README「许可」章节明确覆盖） |
| 网页插件移植（`dsh-plugin/`） | [YCTS-otree/VK-1](https://github.com/YCTS-otree/VK-1) | MIT |
| 本仓库 | 仅移动端适配，不改玩法 | MIT |

> 本仓库**不是**上游实现，只是把网页插件搬到手机 WebView 上时需要的适配。
> 玩法、美术、结算节奏全部属于上面两位作者。

## 为什么需要适配

手机上的 DSH WebView 与桌面浏览器有三个根本差别，桌面版参数直接搬过来会失效：

1. **视口极小**：CSS 视口约 361px（1264 物理像素 / DPR 3.5），而上游默认挂件 454px —— 等于 126% 屏宽，开机就是满屏；
2. **输入是触摸**：没有鼠标悬停、右键菜单不可靠、`touch-action` 缺省时拖动会被浏览器当成滚动页面；
3. **屏幕边缘属于系统**：底部是全面屏手势区，常驻输入框也占掉一大块。

## 改动清单（现象 → 根因 → 改法）

| # | 现象 | 根因 | 改法 |
| --- | --- | --- | --- |
| 1 | 挂件满屏、压住聊天 | 默认 454px 在 361px 视口里是 126% | 窄屏 `DEFAULT_SIZE` 按屏宽 36% 自适应（clamp 128–192）；localStorage 里继承来的旧默认 454 视为未设置 |
| 2 | **完全拖不动** | 指针事件挂在 `document` 上、事件目标不是挂件本身，缺 `touch-action` 时触摸被判成滚页面 → 随即 `pointercancel` | `touchstart`（capture / passive:false）命中挂件即 `preventDefault`；`touchmove` 再兜一道。**注意：`touch-action` 必须手势前生效，在 `pointerdown` 里改已经晚了** |
| 3 | 手机上找不到菜单 | 菜单入口是 hover 按钮 + 右键，触摸端都没有 | 补长按 480ms 开菜单（一移动就取消，不影响拖动） |
| 4 | 默认位置压住标题/输入框 | 默认锚点在左上贴边 | 窄屏默认右下角，底部让出屏高 16% |
| 5 | 道具落进全面屏手势区，误触 | "地面" = 视口底部 = 手势区 | `viewportRect().bottom` 减去安全边距（屏高 3%，夹 18–40px） |
| 6 | 松手几乎没有惯性 | 只取最后一帧瞬时速度再 ×0.35，手一停就归零 | 移植上游 `ThrowVelocity()`：150ms 窗口逐段速度取中位数 + 阈值 12 + 限幅 |
| 7 | 惯性过大、一甩就飞 | 上游限幅 4200/1700 是「454px 挂件 + 桌面视口」量纲 | 限幅 × `size/454`（下限 0.15） |
| 8 | 盆掉得急、几乎不弹 | 重力等常量同样是桌面量纲，缩小后相对屏幕大 3.5 倍 | 重力/磁吸/滑动阈值按尺度缩放（重力取 `sqrt(k)` 折中） |
| 9 | 白饭穿过扣在头上的铁盆 | 插件比上游**多**了一个跳过条件：`ra.onHead \|\| rb.onHead` | 对齐上游，只跳过 `Fed` |
| 10 | 白饭砸到扣头铁盆不回弹 | 扣头铁盆位置每帧重置、速度被清零，碰撞位移只有一帧（16ms）看不见 | 新增受撞偏移 `hitX/hitY` + 阻尼回弹 + 位移钳制（挂件尺寸 5%） |
| 11 | 碰撞只推开、不反弹 | 上游的速度交换带条件 `(va−vb) > 0`，白饭垂直砸静止铁盆时不成立，只剩位置分离 | 改为无条件按接近速度弹开（0.55 → 0.9），并清掉被撞一方 `grounded`；`RESTITUTION` 0.5 → 0.6 |

## 安装

```sh
# 让 agent 安装：把本目录交给 plugin_manager 的 install_bundle
# 或命令行：
dsh plugin --profile web add <本目录绝对路径>
```

装完**重启 `dsh web`**（宿主会把 `widget.js` 读进内存，不重启换不上），再刷新页面。

## 已知限制

- 桌面端行为不变：以上判定都以窄屏（< 700px）为条件，非窄屏走原逻辑；
- 上游若是更新 `widget.js`，本补丁需要在新版本上重打（`mobile-adaptation.patch` 就是为此准备的）。
